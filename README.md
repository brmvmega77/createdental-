# Create Dental

Портал для клиник, главного техника и исполнителей. Нужен Node.js 20 или новее.

## Запуск

```sh
SUPPORT_TOKEN_FILE=.data/support-token npm start
```

Локальный адрес: http://127.0.0.1:4173/. Проверка синтаксиса: `npm run check`.

На первом экране одна форма входа для всех. Клиника регистрируется по ссылке под кнопкой «Войти»: нужны название, телефон, email, город, адрес и пароль (от 8 символов). Техники входят по рабочему email и паролю, которые задаёт главный техник в разделе «Команда». Главный техник входит по выданным ему логину и паролю; общий ключ оператора чата для входа в портал не подходит. Ссылка «Забыли пароль?» показывает порядок обращения к главному технику; автоматическая отправка письма пока не настроена. Сеансы хранятся в `.data/sessions.json`, имеют срок жизни 7 дней и сохраняются после перезапуска. Файлы `.data` содержат персональные данные и должны быть доступны только пользователю сервера; ежедневные резервные копии создаются в `.backups` (по умолчанию сохраняются 14 последних). Для восстановления остановите сервер и верните нужный снимок `.backups/snapshot-*` в `.data`.

Адреса страниц используют пути: `/login`, `/register`, `/forgot-password`, `/clinic`, `/clinic/orders`, `/clinic/orders/{id}`, `/technician`, `/technician/team`, `/technician/messages`, `/technician/analytics`, `/worker`, `/worker/orders`. Старые адреса с `?role=` автоматически заменяются на новые.

Данные заказов, клиентов, сотрудников и этапов сохраняются в `.data/portal.json`; учётные записи с хешами паролей — в `.data/accounts.json`. Исходные демонстрационные клиники, техники и заказы удаляются при загрузке данных; добавленные вручную записи сохраняются. Клиника видит только свои заказы, техник — только назначенные ему. Отключённый или уволенный техник теряет доступ к кабинету.

Для сброса всех пользователей и создания одного главного техника запустите `node reset-users.mjs ИМЯ`, передав пароль через стандартный ввод. Эта команда удаляет учётные записи, карточки клиник и сотрудников, а также назначения исполнителей; сами заказы сохраняются. После сброса перезапустите сервер, чтобы закрыть старые сеансы.

Главный техник может добавлять и редактировать техников, назначать заказы и принимать работы после проверки качества. У новых техников обязательны email и пароль. Клиники, добавленные главным техником, могут зарегистрироваться по тому же email и получить доступ к своей карточке.

Каждая клиника получает случайный код подключения вида `CD-CL-12345678`. Код отображается и копируется в разделе главного техника «Заказчики». Он используется только для создания запроса на подключение Telegram-чата.

Сообщения клиник сохраняются отдельно по каждой учётной записи в `.data/clinic-messages.json` и доступны главному технику в разделе «Сообщения». Подсказки российских городов и адресов поступают через публичный сервис Photon; при его недоступности поля можно заполнить вручную.

## Telegram и голосовые заказы

Бот может работать в групповых чатах с клиниками. Для первого подключения код клиники должен присутствовать в названии чата. Бот создаёт запрос, а главный техник подтверждает его в панели интеграции. После подтверждения код можно убрать из названия: дальнейшая связь выполняется по внутреннему Telegram chat ID. Входящие тексты и расшифровки голосовых сообщений появляются в разделе главного техника «Сообщения», а ответы главного техника отправляются обратно в связанный Telegram-чат со статусом доставки.

SpeechKit расшифровывает голос, а YandexGPT определяет безопасное действие: создать, изменить или отменить заказ, показать статус, принять доставленную работу либо запросить доработку. Изменяющие CRM действия выполняются только после нажатия кнопки подтверждения в Telegram. Если по фамилии найдено несколько заказов, бот показывает список подходящих заказов. Поддерживаются голосовые сообщения до 5 минут и 10 МБ; длинные записи безопасно делятся на части перед распознаванием.

Секреты не входят в репозиторий и читаются из каталога `.data`:

- `.data/telegram-bot-token` — токен BotFather;
- `.data/yandex-speechkit-api-key` — ключ с областью `yc.ai.speechkitStt.execute`;
- `.data/yandex-gpt-api-key` — ключ с областью `yc.ai.languageModels.execute`;
- `.data/yandex-folder-id` — ID каталога Yandex Cloud.
- `.data/yandex-disk-token` — OAuth-токен Яндекс Диска с доступом к чтению и записи. На Диске файлы хранятся только в `Клиенты/<ID заказа>/`; вложения Telegram загружаются туда после выбора и подтверждения заказа.

Файлы должны содержать только соответствующее значение без кавычек. Для контейнера файлы и каталог `.data` должны читаться пользователем UID 1000. После добавления секретов перезапустите контейнер. При успешном запуске в журнале появится `Telegram bridge enabled`; без полного набора секретов портал продолжит работать, а журнал покажет, что интеграция отключена.

Для простой безопасной настройки запустите в каталоге проекта `bash setup-telegram-secrets.sh`. Скрипт по очереди запросит пять значений скрытым вводом, настроит права доступа, пересоберёт контейнер и покажет журнал запуска. Значения не передаются в Git и не выводятся на экран. Те же значения можно вводить по одному в профиле главного техника.

Аналитика раздельно показывает созданные заказы по дате создания, выручку после принятия врачом по фактической дате приёмки и оплаты по фактической дате отметки платежа. Главный техник может отмечать и отменять отметку оплаты в карточке принятого заказа; это не интеграция с банком и не расчёт прибыли. Вложения заказов, сообщений и фотографии результата поддерживают изображения, PDF, STL, PLY, архивы, Word, Excel и текстовые документы до 200 МБ. После подключения Яндекс Диска браузер отправляет файл прямо в закрытую папку `/Create Dental`, а CRM получает только подтверждённые метаданные и временные ссылки. Поэтому крупные файлы не занимают диск и канал сервера. Пока Диск не подключён, кабинет сохраняет совместимость со старым локальным хранилищем. Скачивание доступно только клинике-владельцу заказа, главному технику и назначенному исполнителю. История хранит создание и изменение заказа, смены этапов и исполнителей, причины доработки и автора каждого действия.

Для файлов Telegram крупнее 20 МБ используется кнопка «Файл до 200 МБ». Бот предлагает выбрать активный заказ и выдаёт одноразовую ссылку на два часа. Страница уже привязана к клинике и заказу; повторно вводить фамилию или ID не нужно. После загрузки файл автоматически появляется в карточке заказа.

## Публикация

`docker compose up -d --build` запускает приложение на `127.0.0.1:4173`; порт намеренно не открыт в интернет. Поставьте перед ним Caddy или Nginx и включите TLS для домена, затем проксируйте HTTPS на локальный порт. В reverse proxy нужно перезаписывать `X-Forwarded-Proto`; при `HTTPS_REDIRECT=1` приложение перенаправляет незашифрованные запросы и включает HSTS для HTTPS. Можно запустить Node напрямую с парой переменных `TLS_KEY_FILE` и `TLS_CERT_FILE` (пути к приватному ключу и сертификату); для принудительного редиректа задайте `HTTPS_REDIRECT=1`. Не включайте редирект за прокси, который не передаёт корректный `X-Forwarded-Proto`. Резервные копии размещаются в отдельной папке `.backups` на том же сервере: для защиты от отказа диска копируйте её также на отдельное хранилище. Папки `.data` и `.backups` должны быть доступны на запись пользователю контейнера (UID 1000); владелец файлов не должен открывать их другим пользователям. Файл `.data/support-token` также должен читаться UID 1000. Старую панель оператора `/support.html` сохраняем для ранее созданных диалогов; новые обращения клиник отображаются в кабинете главного техника.
