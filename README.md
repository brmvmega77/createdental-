# Create Dental

Портал для клиник, главного техника и исполнителей. Нужен Node.js 20 или новее.

## Запуск

```sh
SUPPORT_TOKEN_FILE=.data/support-token npm start
```

Локальный адрес: http://127.0.0.1:4173/. Проверка синтаксиса: `npm run check`.

На первом экране одна форма входа для всех. Клиника регистрируется по ссылке под кнопкой «Войти»: нужны название, телефон, email, город, адрес и пароль (от 10 символов). Техники входят по рабочему email и паролю, которые задаёт главный техник в разделе «Команда». Главный техник входит по выданным ему логину и паролю; общий ключ оператора чата для входа в портал не подходит. Ссылка «Забыли пароль?» показывает порядок обращения к главному технику; автоматическая отправка письма пока не настроена. Сеансы хранятся в `.data/sessions.json`, имеют срок жизни 7 дней и сохраняются после перезапуска. Файлы `.data` содержат персональные данные и должны быть доступны только пользователю сервера; ежедневные резервные копии создаются в `.backups` (по умолчанию сохраняются 14 последних). Для восстановления остановите сервер и верните нужный снимок `.backups/snapshot-*` в `.data`.

Адреса страниц используют пути: `/login`, `/register`, `/forgot-password`, `/clinic`, `/clinic/orders`, `/clinic/orders/{id}`, `/technician`, `/technician/team`, `/technician/messages`, `/technician/analytics`, `/worker`, `/worker/orders`. Старые адреса с `?role=` автоматически заменяются на новые.

Данные заказов, клиентов, сотрудников и этапов сохраняются в `.data/portal.json`; учётные записи с хешами паролей — в `.data/accounts.json`. Исходные демонстрационные клиники, техники и заказы удаляются при загрузке данных; добавленные вручную записи сохраняются. Клиника видит только свои заказы, техник — только назначенные ему. Отключённый или уволенный техник теряет доступ к кабинету.

Для сброса всех пользователей и создания одного главного техника запустите `node reset-users.mjs ИМЯ`, передав пароль через стандартный ввод. Эта команда удаляет учётные записи, карточки клиник и сотрудников, а также назначения исполнителей; сами заказы сохраняются. После сброса перезапустите сервер, чтобы закрыть старые сеансы.

Главный техник может добавлять и редактировать техников, назначать заказы и принимать работы после проверки качества. У новых техников обязательны email и пароль. Клиники, добавленные главным техником, могут зарегистрироваться по тому же email и получить доступ к своей карточке.

Сообщения клиник сохраняются отдельно по каждой учётной записи в `.data/clinic-messages.json` и доступны главному технику в разделе «Сообщения». Подсказки российских городов и адресов поступают через публичный сервис Photon; при его недоступности поля можно заполнить вручную.

Аналитика раздельно показывает созданные заказы по дате создания, выручку после принятия врачом по фактической дате приёмки и оплаты по фактической дате отметки платежа. Главный техник может отмечать и отменять отметку оплаты в карточке принятого заказа; это не интеграция с банком и не расчёт прибыли. Файлы JPG, PNG, PDF, STL и PLY сохраняются в `.data/order-files`, ограничение — 50 МБ на файл. Скачивание доступно только клинике-владельцу заказа, главному технику и назначенному исполнителю. История хранит создание и изменение заказа, смены этапов и исполнителей, причины доработки и автора каждого действия.

## Публикация

`docker compose up -d --build` запускает приложение на `127.0.0.1:4173`; порт намеренно не открыт в интернет. Поставьте перед ним Caddy или Nginx и включите TLS для домена, затем проксируйте HTTPS на локальный порт. В reverse proxy нужно перезаписывать `X-Forwarded-Proto`; при `HTTPS_REDIRECT=1` приложение перенаправляет незашифрованные запросы и включает HSTS для HTTPS. Можно запустить Node напрямую с парой переменных `TLS_KEY_FILE` и `TLS_CERT_FILE` (пути к приватному ключу и сертификату); для принудительного редиректа задайте `HTTPS_REDIRECT=1`. Не включайте редирект за прокси, который не передаёт корректный `X-Forwarded-Proto`. Резервные копии размещаются в отдельной папке `.backups` на том же сервере: для защиты от отказа диска копируйте её также на отдельное хранилище. Папки `.data` и `.backups` должны быть доступны на запись пользователю контейнера (UID 1000); владелец файлов не должен открывать их другим пользователям. Файл `.data/support-token` также должен читаться UID 1000. Старую панель оператора `/support.html` сохраняем для ранее созданных диалогов; новые обращения клиник отображаются в кабинете главного техника.
